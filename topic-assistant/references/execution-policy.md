# 有限执行策略

本文件只解决任务空转、无边界扩展和验收返工。学术质量仍由各阶段参考决定；这里的次数和时间是失败保险，不是“全面检索”或“读懂全文”的证明。用户明确指定的范围、期限和继续方式优先，但不得把模糊的“全面”“完善”“再检查”解释为无限工作。

## 执行档位

| 档位 | 触发条件 | 默认范围 |
| --- | --- | --- |
| light | 单个问题、段落或来源核查 | 定点阅读后直接回答；不建运行目录，不查新 |
| standard | 未明确要求正式成品的选题、比较或评估 | 指定目录内必要阅读与本地查找、共享热点、候选资格审核、本地排序、最终候选联网核验、Markdown 报告及最终入选题的逐题综述；证据不足则交待补证稿 |
| formal | 用户明确要求全面精读、可直接使用的综述、正式报告或开题稿 | 执行实际需要的完整阶段，在最终候选联网核验后交付 Markdown；仍受本文件的修复和停止上限约束 |

无法判断时选 standard。不得因为输入文件多、已有运行目录或用户使用“全面”一词就自动升级 formal；交付物和覆盖要求足以表明正式成品时才升级。standard 与 formal 都为最终入选题写综述，区别在阅读覆盖和成品深度，不在有没有综述。只有用户明确放弃综述并保存原话，或本次没有最终入选题，才能省略。任务开始时用一句话说明档位和预计阶段；报告类任务直接说明将交付 Markdown。

## 操作上限

- 每个阶段一次主处理，最多一次针对明确缺口的修复。修复必须写清要解决的问题，不能以“再全面检查一次”为目标。
- 每个保留题在指定目录内执行一组计划好的基础查找，最多增加一组缺口补查；一组可含必要的同义词和反证线索。不得访问目录外路径或外部平台。补查不改变题目、排序、证据强度或限制时立即停止。
- 候选前[共享热点](hotspot-scan.md)最多六条实际查询、十二个直接来源目标和十二分钟；学科所需查询类别全任务共享。最终核验只覆盖合格题中排序后的最多五题，每题最多两条实际查询、三个目标；理论查新、热点与最终核验合计最多展开四篇外部学术全文。复用有效来源，不凑次数、不同查询不打包绕预算。
- 不核验淘汰项，不补位。某网站访问失败后同文章至多一条正规替代路线，仍计预算；工具整体不可用才全局停止，不从单站失败推断全网故障。不轮询、不等恢复。
- 每份材料按任务需要读一次；确有遗漏时最多定点回读一次。用户明确要求完整精读时一次主处理覆盖全文，但不因此反复从头阅读。
- 同一校验器最多运行两次：首次检查和一次修复后的复查。相同输入和参数不得重跑；访问状态没有变化时不得重试失败请求。
- 全任务最多一次回到已完成的上游阶段。新材料或用户改变约束不计为失败重试，但只重开实际受影响部分。
- standard 六十分钟、formal 九十分钟结束本轮；最后十五/二十分钟停止新增阅读检索，用于成稿、核对、审校和交付，预计不足则更早收拢。网络耗时包含在总时限内。证据或书目不完整时交付实际支持的待补证综述，不以删章赶时限。不能可靠计时时以操作上限为边界；只在阶段边界看时间。

到达上限不是继续简化同一尝试的理由。保存已完成成果，按真实状态结束；后续只有用户明确继续或提供新条件时才能恢复。

## 冻结与返工

流程正常向前：`本地证据 -> 共享热点与理论索引 -> 短设计与准入 -> 排序取最多五题核验 -> 一次实质复核与 preflight -> 最终名单及逐题综述 -> 内容冻结 -> 一次语言审校 -> check 后按真实状态交付 -> 结束`。preflight 复用角色 3 的既有审核，不新增语义复核轮次。理论卡按需读取，相同卡复用；新研究任务按[知识协议](knowledge-protocol.md)定向查新并核验增量发布，不全量刷新。已有相关知识最多2查询/4直接目标，新学科或缺口最多4查询/8目标，共享总时间和外部全文预算；写作审校及同任务继续复用。断网无适用知识则纯论文，不阻断阅读或交付。

题目冻结后，淘汰题不再展开。内容冻结表示事实、论点、引用、书目及逐题综述验收已经核定；随后语言编辑不得增加新主张。prepare 只在内容冻结后执行，seal 后不再修改审校源稿。

问题按影响处理：

- critical：虚构或错误引用、来源不能支持核心结论、题目或对象错误、成品损坏。可使用唯一一次上游回退，定点修复后重新冻结受影响内容。
- major：必要章节缺失、比较或论证明显不完整，但不推翻已核证据。只在当前阶段修复一次，不重新全量查找或阅读。
- minor：措辞、标点、Markdown 层级或局部重复。在封存前定点修改，并纳入已有审校及最终指纹；封存后不为这类问题改动本轮交付稿，可说明并留待用户下一轮修订，不重开全文审校。

任何文件字节变化都会影响指纹，不能把格式修改视为天然不使记录失效。封存前的局部修正仍在本轮既有审校内处理；封存后只有影响理解或引用正确性的 critical 错误才能使用尚未消耗的全局回退并重新绑定实际修改。其他问题不反复封存或整稿重审。

## 无进展与终态

出现任一情况即判定无进展：同一错误第二次出现；相同输入没有新输出；补查没有改变任何判断；连续两次实质动作均未增加证据、产物或状态变化；工具需要等待但没有可观察的运行会话。不得靠重复自检、重复读取规则、重复封存或轮询维持任务。

每轮必须以一种终态结束：

- complete：用户要求的交付已经完成并通过适用验收。
- limited：成果可用，但证据、访问或非关键验收存在已说明的边界。
- blocked：缺少用户选择、权限、必需输入或外部条件，继续动作不能推进。
- checkpointed：达到时间或操作上限，已保存可恢复成果，并列出已完成阶段、剩余阶段和恢复入口。

终态说明只报告实际完成、限制和一个明确的后续入口，不生成新的自评报告。凡已生成报告或其他交付文件，必须列出最终 Markdown 的绝对路径或可点击链接；只报“已完成”而不提供路径不算交付。limited 和 checkpointed 是有效结束，不得为了追求 formal-ready 自动继续。

## 阶段验收分工

内容冻结前检查事实、证据、引用、综述结构和候选一致性；语言阶段只处理表达及修改保真；最终校验只检查 Markdown 结构、引用关系、内容指纹和审校记录。后一个阶段不得无故重复前一阶段的完整审核。输入未变且已有检查通过时复用结果。

preflight 失败时不进入长报告生产；在既有修复额度内修正或剔除，仍未解决就保存并交付实际完成的阶段 Markdown，明确“未通过验收草稿”及缺口，不把未验收方案列为已确认推荐。最终 check 输出 errors、warnings 和 delivery，非零退出码不能忽略；同样最多首次加一次定点修复后的复查。若仍失败，停止并交付已有草稿及错误说明，终态为 limited 或 checkpointed，不能写 complete。校验工具不可执行时说明“自动验收未执行”，不编造检查结果。

check 返回的路径仅表示实际存在的报告，不能把 unvalidated-draft 当作通过；若文件不存在则如实说明未生成。失败提示放交付说明，不必为再次封存反复改写全文。结构通过与学术问题成立分开报告，不对其他模型或宿主作自动强制执行保证。
