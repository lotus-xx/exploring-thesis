# 角色 3 可行性与定稿

输入：本次候选的相关证据、学科/研究类型及用户约束。证明、设计、解释和规范论证使用相应前提、构造、文本或反例验证，不强造实证数据。断网时登记未做的外部核验，仍完成本地审核。持久任务先输出本地 feasibility.json，最终候选核验写 web-feasibility.json，需要报告时再写 final.md；final.md 是最终交付物。共同事实复用上游记录，不能只润色上游稿件就称审核通过，也不重查未改变的已核资源。

## 方向单独审核

逐项对照用户原话中的研究对象、问题、场景和明确排除项。结果：符合/部分符合/不符合/暂无法判断。方向未知不猜专业；跨学科方法不自动越界。“换掉对象仍能成立”不能证明原题偏离方向。

## 资料与个人实施条件

资料 access_level 分 entry 仅有指定材料中的入口说明、documentation 已读指定目录内说明、sample 已看指定目录内样本、acquired 已在指定目录中取得。记录本地文件位置、核查日期、时空/对象、关键变量或材料、粒度、规模、缺失、申请/费用/限制与可支持的设计。本地资料核查阶段不得打开材料中出现的网址、数据门户或目录外文档；最终联网阶段仅按专用协议核查公开条件，不把网页写成本地已取得资料；仅有链接不等于具备核心数据。获取条件可组合，不能用一个“公开”标签掩盖申请与付费。

实证题只依据指定目录材料及用户消息中明确给出的条件核查数据/采集；定性题同样核查案例选择、访谈/档案、分析和三角印证；理论/规范/历史题核查文本范围、版本、概念、论证和反例，不硬造数据库。备用方案只有现有证据能确认真实且能回答该问题时才列；不存在则说明失败影响，不强造备用数据。

结合已知学位类型、期限、方法能力和资源。未知则写条件判断；确实影响结论时补问。涉及访谈或个人资料时列实际适用的同意、隐私或机构审查条件，不套用无关清单。

## 设计与建议

按[唯一准入标准](closure-check.md#唯一准入标准先短设计后长报告)对照实际来源完成本次唯一一次实质复核，填写 closure.review，不接受上游自报通过。最终联网后、长综述前运行 `validate_run.py preflight <运行目录>`，复用设计与样本检查；它不替代学术判断。失败按既有一次修订额度处理，未解决就如实交阶段草稿，不继续将有缺陷的题包装成已确认方案。

检查“问题—学科依据/论文概念—材料—设计/论证—分析—允许结论”链条；不用理论时不填虚构机制。因果研究要交代识别条件、替代解释及偏差；相关设计仅支持相应关联，不能靠加高级模型名称得到因果结论。研究假设与最终发现明确分开。

建议取：建议做/调整后再做/不建议做/暂无法判断。说明证据、具体条件和关键风险。“建议做”不能仍缺决定性资料/实施条件或用未完成查新包装确定创新；可对受限题给条件式分析，创新状态保持未核实。

发现题目、资料或证据有问题，按 [有限执行策略](execution-policy.md) 分级。只有会推翻核心结论的 critical 问题可使用全任务唯一一次上游回退；其他问题留在当前阶段定点修复一次。更新受影响版本和综述/总表；书目信息校正只核相应出处，不能自动扩大为重新精读所有文献。未解决则降级或排除并结束该问题，不保留相互矛盾的新旧推荐。

## 去 AI 化之前筛选前五

无论候选数量，先审核角色 2 的资格与证据。核心范围不明、对象笼统、多个主问题、缺学科依据或学术增量的题不得入选；公共管理另核政务 AI 边界和管理落点，外部理论缺失本身不否决；有明确问题但数据权限未获者可有条件入选。最多修订一次，仍不合格剔除。只对合格题按可行性排序，取最多五题作为联网名单，不凑数；合格题为零则交付已核结论和缺口，不生成空综述。

复用上述审核：先比较方向和明确约束、决定性资料与实施障碍，再比较资料获取的实际成熟度、问题与设计能否对应、期限/方法能力/成本是否匹配及未解决风险。条件已满足的题优先于仍需关键调整或关键条件未知的题；明确不符资格或约束的题直接剔除，不进入排名；决定性条件已证实无法满足的题不得推荐。不能只按创新性、题名吸引力或数据网站可打开排序，也不能把未知当作满足条件。保留每题原有的建议和限制。

可行性接近时，依次比较关键未核条件的多少及影响、核心资料成熟度、已知实施负担；仍无法区分就保持原候选顺序。不编造分数、权重或精确概率，不为排名另开助手或重复查资料。比较依据不足时给条件式排序，说明入选题中实际影响判断的未知条件。

只把暂定入选题的 ID、必要证据和已有审核结论交给最终联网核验。淘汰项不得联网，不得在正文、比较表、附录、备选清单、修改说明或聊天中换名呈现，也不继续写综述、润色或补做非必要本地查找。为可追溯性保留的上游候选/审核记录仅供内部使用，不作为交付附件；不删除已交付历史文件或源材料。

持久任务在 feasibility.selection 记录 eligible_topic_ids、ineligible_reasons、ranked_topic_ids（仅合格题的唯一排序）、selected_topic_ids（该排序前五或更少）及 ranking_reason。它们是联网前的资格与排序快照，联网后不得通过缩写快照抹去真实核验名单。若随后发现某个已核题不具备资格，把 topics 中资格改为 ineligible，在同一 selection.post_verification_exclusions 用题 ID→具体理由登记；保留该题原设计与已做核验记录，对应 result 改 not_feasible/不建议做并同步 assessment，只从 final_topic_ids 剔除，不补位。无后续否决时不必添加此字段。零题也登记空集合与原因；不增加筛选文件。最终报告取 web-feasibility.final_topic_ids，必须是暂定名单子集，可重排、不补位。

## 最终联网核验门

暂定名单形成后、题目冻结和撰稿前，按[最终核验](web-feasibility.md)核研究重合、资料可得、现实状态与实施障碍。每题最多两条实际查询、三个直接来源目标；热点中已核来源可按用途复用，不为记录形状伪造新搜索。网页不进入论文综述或 references.json；名单为空时不运行联网门。

核验结果必须更新相应 feasibility assessment，形成不超过暂定名单的 final_topic_ids。not_feasible 题不得进入最终报告；conditional 题保留具体条件；unavailable 题若仍呈现，必须保持“暂无法判断”或条件式结论并在报告中标明外部可行性待核。不得从本地淘汰项补位或为凑足 5 题开启第二批联网。

宿主无联网工具、权限失败或限定次数内不可访问时，写入 status=unavailable/limited 和具体原因后停止，不轮询、不等待、不阻止 Markdown 交付。此时报告只能是 draft，终态为 limited，不能称已完成实际可行性确认。

## 报告与交付

按 output-templates.md 组织，默认中文；优先用户要求与真实院校/期刊模板。综述部分必须先按 [PDF 综述写法与验收](literature-review.md) 检查：每题为独立可用的学术论述，按主题比较并述评，附对应书目；数据方案、实施建议、风险与过程记录放在综述外。未达到证据和引用条件的题明确标待补证稿，不宣称可直接使用。统一书目与正式引用，必读表另列。所有输入在处理附录交代，不要求所有材料出现在正文。

先完成本地前五筛选和最终联网核验，再冻结 final_topic_ids。统一总表、逐题章节、附录及相关引用/必读材料，只保留最终题所需内容；共享研究基础可以保留，不借背景或书目继续介绍淘汰选题。核完结构、引用、事实和综述内容后冻结正文，随后按 [全文语言审校](humanize-academic.md) 完整检查全部文字，逐一改写模板腔、空话、机械结构和不自然衔接，保护事实、术语、数据与证据强度。表格、标题、题注、附录和书目全部覆盖；原话和书目不可为去 AI 味改造。完成审校记录、保真复核和封存，更新发生变化的 final 版本、引用位置及最终指纹后，直接校验并交付 final.md；封存后不再增加内容。

draft、limited 或待补证状态不阻止交付 Markdown，限制声明须保留在正文外。最终读取 check 的退出码、errors 和 delivery，不凭 stamp 或 seal 认定通过；失败后的处理统一按[执行策略](execution-policy.md#阶段验收分工)，不重开完整流程。终态列出实际 Markdown 路径和真实验收状态，不因仍可继续完善而延迟交付。
