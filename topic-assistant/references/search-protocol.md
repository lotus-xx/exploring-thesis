# 指定目录内检索协议

本协议只规定本地论文的查找范围，不是总联网开关。用户未提供至少一个论文目录绝对路径时，立即停止，不读取论文、不创建运行目录、不进行检索，只回复：`请指定需要读取的论文文件夹绝对路径。`

## 硬边界

1. 仅枚举、读取和分析用户指定文件夹及其子目录。不得猜测其他路径，不得扫描其上级、同级、桌面、用户主目录或全盘。
2. 本地查找不打开文件内链接、不访问其他本地目录。新的有效研究任务另按知识协议定向理论查新；最终推荐任务再按热点与最终可行性协议受限联网；其外部记录与本地论文证据分开。
3. skill 自身规则、脚本以及本次运行目录内由指定材料生成的记录只用于执行和校验，不作为论文证据，不得借此扩大来源范围。
4. 目录内材料不足时如实降低结论强度，保留未知或待补证状态；不得以“完善检索”为由越界。

## 本地查找

先在允许目录中盘点文件类型和层级，再按任务需要查找题名、作者、关键词、概念、方法、结论和引用线索。每次查找都必须把路径参数限定为已登记的 `allowed_input_roots`，不能从当前目录、父目录或模糊通配位置起搜。

相同任务内，同一文件和同一表达式已经检查且内容未变时复用结果。只有明确缺项才增加一次定点查找；查找不改变题目、排序、证据强度或限制时立即停止。目录内找不到只说明“指定材料未覆盖”，不推断整个领域不存在相关研究。

## 差异与反证

每个拟推荐问题只基于指定目录内实际读到的材料核对：最接近研究做了什么、差异是否只是换对象、是否有不同术语表达同一问题、相邻场景已有何解释、是否存在反向结果。支持和削弱选题的材料都要记录。

gap_state 只使用 `local_question`、`candidate`、`covered` 或 `unverified`。严格目录模式不能证明领域检索覆盖，因此不得使用 `bounded_support`，不得写“尚无研究”“国内外无人研究”等全域结论。`topics.json` 的 `search_ids` 保持空数组，仅保留该字段作格式兼容；本 skill 不创建 `search-log.json`。

本地阶段说明指定目录及覆盖限制；知识库检索与论文检索范围分别登记，内部知识不能扩大论文范围。候选形成前按[共享热点核对](hotspot-scan.md)获取问题背景；资格与可行性筛选后按[最终核验](web-feasibility.md)检查最多五题。两阶段不替代本地文献阅读，不补写综述，不向其他本地路径扩展。
